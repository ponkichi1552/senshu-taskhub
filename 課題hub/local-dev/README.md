# ローカル起動

Apps Scriptの画面とサーバー関数を、このフォルダーだけで確認するための開発用サンドボックスです。実際の `Code.gs`、`UniversityNotices.gs`、各HTMLを使い、GoogleのAPIだけをローカルの `SpreadsheetApp` / `GmailApp` 模擬環境に置き換えます。

## ソース構成

サーバー側は `Code.gs` に共有設定とWebアプリの入口を置き、メール同期、inCampus/Classroomの解析、通知一覧、拡張機能APIを機能別の `.gs` ファイルに分けています。画面側は `Scripts*.html` と `Styles*.html` に分け、`Index.html` が読み込み順を管理します。GASへ反映する時は `clasp push` が対象ファイルをまとめて送ります。回帰テストでは `taskhub-split/workspace/taskhub-split/` のミラーと一致することも確認します。

## 起動

プロジェクトのルートで実行：

```sh
./local-dev/start.sh
```

ブラウザーで表示された `http://127.0.0.1:4173/` を開きます。テスト操作とシートの中身は `http://127.0.0.1:4173/__local` で確認できます。終了はターミナルで `Ctrl+C`。

Node.jsのシステムインストールがあればそれを使います。Codexの同梱ランタイムも標準のユーザーディレクトリから探します。別の実行ファイルを指定するときは `TASKHUB_NODE=/path/to/node ./local-dev/start.sh` を使います。実行環境へのパスを変更する場合は `TASKHUB_RUNTIME_ROOT` または `TASKHUB_NODE_MODULES` を指定できます。

## 入っているテストデータ

- 架空データ解析：同じ課題の追加＋更新と、別課題が同じメールにある例。
- 仮想心理演習／サンプル情報設計：1通に複数授業の課題と提出記録がある例。
- Google Classroom：締切付きの新規課題例。
- `local-dev/.data/test-spreadsheet.json`：ローカル個人用保存先と読み取り専用テストケースExcelを別々に保存します。シート名、見出し、行、完了状態を保存します。初期化ボタンで架空メールから再作成できます。

テストケースExcelから開始すると、ワークブックの「テストメール」シートにある架空メールもGmail模擬データとして取り込みます。期限切れ・今日・明日・今週・来週の締切を同時に置き、日付だけ、0:00、日付のないメール、存在しない日付、投稿／受信日時やURLにしか日付がないメール、返却通知、お知らせ、1通内の複数課題、二重取得、提出記録を試します。合否と期限区分ごとの件数はテスト画面の実行結果に出ます。「仕様カバレッジ」シートは修正番号1～15とREADME要件を回帰テストへ対応づけています。7と11は指定どおり変更対象外です。

通常のアプリ画面は保存済み一覧を先に読み込みます。メール同期は15分間隔のGASトリガーと画面の「更新」で行い、開いているタブの15分更新は保存済み一覧の再読込だけです。画面の更新は非同期で実行し、同期中も既存カードを残して完了・失敗を通知します。新規作成した保存Excelだけ初回に20日分を取り込みます。既存Excelでは保存行内の最新受信日時と前回同期開始日時を基準に増分検索し、週次の63日全照合はしません。リンクを開くたびに全期間を検索する処理も避けます。テスト画面の「サンプルメールを取り込む」は実際のGAS関数 `saveClassroomMailsToSheet()` を実行し、その出力を個人用保存先へ保存します。課題を完了・取消すると同じGAS関数を通じて行状態が変わります。

全回帰テストとローカルHTTP画面の通し確認：

```sh
./local-dev/test.sh
```

HTTP通し確認には一時フォルダーを使い、普段のテストシートデータを変更しません。空の初回利用状態から一覧を読んでローカル個人用ブックと見出しを作成し、更新RPCで20日分の架空メールを書き込み、返された課題が画面に表示されるところまで確認します。その後、テストケースExcelを実際のGAS取込関数へ読み込み、受信日時の同期・重複排除・期限位置・期限グループ・異常系メールの期待結果を確認します。テストケースExcelを参照元にしたON状態では、Gmail取込が個人用保存先だけを更新しテスト画面へ混ざらないこと、完了状態が利用者設定だけに保存されること、拡張機能のPOSTが個人用保存先に書き込まれることも確かめます。

## 保存データExcelでテスト

[`test-fixtures/TaskHub-test-cases.xlsx`](../test-fixtures/TaskHub-test-cases.xlsx) を開き、「テスト設定」シートの「元データの目標位置」と「画面の仮想判定日時」を選んで保存します。すべて架空データで、初期値は「今日まで」、基準期限は 2026/09/10、画面の仮想判定日時は 2026/12/31 23:58（日本時間）です。「テストClassroom」「テストinCampus」「テスト抽出」の期限は固定値で保存され、目標位置に合わせる数式はありません。

ローカル画面（`http://127.0.0.1:4173/__local`）の「テストケースExcelから開始」を押すと、保存済みExcelを個人用保存先と読み取り専用テストケースExcelへ分けて読み込みます。個人用の試験保存データは開始時刻に合わせて作成します。課題一覧で使うテストタブはExcelの日付を変更せず、そのままGAS関数へ渡します。GASは「テスト設定」の目標位置と基準期限、選択済み仮想日時を使い、行を読み取った後にメモリ上の期限だけを移動します。たとえば10/15に「来週以降」を選ぶと、基準期限9/10の行は表示上10/25になります。期限なし・期限未検出の値はそのままです。時刻がない期限は同日の23:59の最終ミリ秒まで有効としてグループ分けし、明示的な時刻付き0:00は前日23:59に補正します。「テスト日時候補」には土曜・日曜・平日・年末年始・JST/UTC境界・平年2月末・月末・閏日前日・閏日を入れています。

「テストメール」内の `{{期限}}` などの置換項目は、Excelで指定した「画面の仮想判定日時」に合わせて作り直します。受信日時はテストを開始した時刻に同期します。アプリの「設定」ではデータ参照ON/OFFとは独立して仮想日時を選べます。テストON中は課題一覧のヘッダーにも日時ボタンが表示され、平日・土曜・日曜・年越し・月末・平年・閏年・JST/UTC境界の候補を切り替えられます。候補は利用者ごとに保存され、テストOFF中は実際の日本時間で分類します。日時変更は保存済みテストデータを再読込し、メール同期は実行しません。元メールの本文日時と受信日時は別に扱います。「期限境界」シートには、全曜日と閲覧日からの期限差63通りに加え、土曜の翌日締切、週の切り替わり、締切分の最終ミリ秒、日付だけ、0:00補正、閏日・月末・年越し、不正値、JST/UTC境界、同一分類内の並び順を載せています。これらは `audit/deadline-cases.cjs` の期待値を共有し、実際の画面分類を自動テストします。

開始後は「アプリ画面を開く」で実際のローカルGASコードを使い、設定からテストケース適用をONにできます。ON時は課題・大学のお知らせだけ読み取り専用のテストケースExcelから表示し、完了状態は利用者ごとに分けます。同期は個人用保存先へ保存し、テスト表示には混ぜません。ローカル環境では架空メールだけを使い、読み込んだ行や操作結果は `local-dev/.data/test-spreadsheet.json` に保存されます。元Excelと本番データは変更されません。別のExcelを使う場合は `TASKHUB_TEST_WORKBOOK=/path/to/file.xlsx ./local-dev/start.sh` で指定します。

## 接続範囲

サーバーは `127.0.0.1` だけで待ち受けます。Googleアカウント、Gmail、Drive、Apps Scriptへ通信しません。架空メール、シート、ユーザー設定は `.data` のローカルファイルに保存します。

これはApps Scriptの完全な実行環境ではありません。GoogleサービスAPIの挙動は必要な範囲だけを模擬しているため、Googleへの認証、実シートの権限・数式・書式、トリガー実行時間などは検証しません。ローカルで仕様を素早く確認した後、独立したテスト用Googleプロジェクトとシートで最終確認できます。
