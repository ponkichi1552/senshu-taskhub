# メール通知シートの保存ルール

- 対象：`補足通知` と `inCampus通知`。
- 1行目は見出しを固定し、2行目からメール受信日時の新しい順に表示します。同じ受信日時なら保存日時の新しい順です。
- メール取り込みで通知シートを整える際に、受信日時が暦で2か月前の同日時以前の行を削除します。月末に同じ日がない場合は対象月の末日を基準にします。一覧の読み取りでは全行の並べ替え・書き戻し・列幅の自動調整を行いません。
- 例：9月13日12時の更新なら、7月13日12時以前の受信メールを削除します。
- 100件／200件の保存件数上限は廃止し、Gmail検索は100スレッドずつページを送って取得します。
- Gmail通知の同期時に、分類・表示タイトル・表示用本文・表示期限・inCampusの複数更新の分割結果を「解析済み通知データ」列へ保存します。課題／お知らせ一覧はこの値を使い、受信メール本文の再解析を避けます。解析ルールのバージョンが変わった場合は次回の通常同期で既存メールを再処理します。
- 元データを保ったまま、同期時に表示用の `課題表示データ`、`完了課題表示データ`、`大学通知表示データ` を再構築します。課題は状態、公開時刻、期限切れ、期限なし課題の保持期限で同期時に絞り込み、状態別に並べたシートへ保存します。大学通知も表示期限を同期時に判定してから保存します。Gmail同期、Classroom API同期、拡張機能からの更新後に再生成し、手動のAPI→Gmail連続同期では最後に一度だけ再生成します。既読・保存状態は従来どおり利用者ごとのUserPropertiesに残します。
- 通常の一覧表示は該当する準備済みシートを一括で読み、本文や期限の再解析・状態／公開時刻／期限の再絞り込み・表示順の再計算をしません。課題の期限グループ判定、グループ内の期限順、各グループ件数、授業別件数は、Gmail／Classroom API同期後に表示用シートを作る時点で確定します。ブラウザーは保存済みグループキー・順序・集計値に沿ってカードを描画します。テストケースは共有シートを書き換えず、選択した仮想日時を使って同じ準備処理をインメモリで再実行します。キャッシュはブラウザが一覧を描画した後に保存し、表示応答後に同期や状態が更新された場合は古いキャッシュ書き込みを拒否します。準備データが再生成中で前回キャッシュもない場合は、元シートを再解析せず再同期を案内します。
- 再処理に使う本文は「本文」列に残します。inCampusメールでは、指定された末尾の「以上」「=====」「専修大学in Campus発信専用」フッターだけ保存時に除去します。提出イベントの「適用済み提出記録」列は従来どおり別に維持します。
- 保存Excelを新規作成した初回の同期だけ、実行時点から20日前までを検索します。検索に失敗した場合は初回フラグを残し、成功後に解除します。
- 既存Excelは保存行内の最新受信日時と前回同期開始日時の遅い方を基準にします。Gmailの `after:` は日付単位なので最新受信日を含む検索を行い、保存済みメッセージIDと正確な受信日時で重複・基準以前のメールを除きます。週次の63日全照合は行いません。
- 7日を超えて遅れて検索対象に現れ、かつ基準日時より前の受信日時を持つメールは自動では拾われない可能性があります。Excelに有効な受信日時がない既存ブックは、広範囲検索をせず同期を見送り、画面右下に理由を表示します。
- 受信日時が空欄・不正な行は、古いと判断できないため残します。
- `inCampus抽出` はメール受信日時を持たないため、この自動削除の対象外です。Gmail上のメールも削除しません。
- ホーム表示のたびに行っていた保存Excelの初期化とトリガー確認は、利用者ごとに初回・週1回のバックグラウンド初期化へ移します。同期トリガーの確認・復旧は別の時間主導トリガーで12時間ごとに行い、サイトを閉じている間も実行されます。
- ホーム課題一覧では、inCampus通知とinCampus抽出を同じ保存シートの一度の読み取り結果から作成します。読み取り処理でシートの整形・並べ替え・書き戻しは行いません。
- 反映には更新後の `.gs`／`.html` ファイル一式をApps Scriptへ反映し、Webアプリのデプロイを更新してください。既に削除された通知行の復元は行いません。

## 更新レコードの状態と排他制御

- 元の14列の後ろに「更新レコード状態」「適用済み提出記録」の2列を追加します。1通に複数のinCampus更新がある場合も元メールを分割・削除せず、各更新の完了状態と提出イベントの適用先をJSONで保持します。
- 既存の完了状態は、その状態が対応していた元の課題に引き継ぎます。同じメールの別課題には一律にコピーしません。
- 表示・完了／取消・メール取り込み・拡張同期は共通のユーザーロックを使います。入れ子呼び出しでは再取得せず、全処理の終了時に書き込みを確定して解放します。
- 旧バージョンの取り込みトリガーやWebアプリを新コードと混在させないでください。旧コードは追加列を含めずに並べ替えるため、課題と状態が別行になるおそれがあります。反映前に保存先スプレッドシートをコピーし、古いトリガー停止→コード・利用中のデプロイ更新→新トリガー作成の順で移行します。

## テストケース適用

- 設定の「テストケース適用」をONにすると、課題・大学のお知らせの参照元だけを固定のテストケース用スプレッドシートへ切り替えます。OFFでは利用者本人の保存先スプレッドシートを読みます。
- テストケース適用中は、固定Excelの日付を読み取り後に仮想日時へ変換して既存の判定経路で検証します。個人用Excelの表示用シートはテスト用Excelの読み取りには使いません。
- 固定テストExcelは参照専用です。テスト中の完了状態、大学のお知らせの既読・保存状態は利用者ごとのUserPropertiesに保持します。テストExcelを更新せず、メール取込・拡張機能POSTの保存先も利用者本人のスプレッドシートのままです。
- ON中もGmailの取込先は元の個人用スプレッドシートのままです。画面の表示は固定テストExcelから読み込み、手動更新や15分トリガーによる実メール取込が個人用Excelを更新しても、テスト表示へ混ざりません。テスト用シートへアクセスできない場合はONにできません。
- 固定スプレッドシートIDは `DEFAULT_TEST_SPREADSHEET_ID` です。`TASKHUB_TEST_SPREADSHEET_ID` Script Propertyを設定するとそのIDを優先します。利用者本人として実行するWebアプリでは、ONにする各アカウントへテスト用スプレッドシートの閲覧権限が必要です。
- `.gs`／`.html` ファイルの更新後はWebアプリのデプロイを更新してください。コード保存だけでは公開中のデプロイに反映されません。

## 大学からのお知らせの表示期間

- inCampus：受信から暦で1か月が経過した通知は非表示。一般の大学からの通知も対象に含めます。
- Classroom：本文に日付がなければ、受信から14日が経過した時点で非表示。
- Classroomの本文に日付がある場合：その日付の当日いっぱいまで表示します。この条件を14日ルールより優先し、日付が過ぎた通知は受信から14日以内でも非表示になります。
- 複数の日付は最も遅い日を採用。年なしの日付は受信日を基準に年越しを補正します。日本時間で判定し、メール末尾の投稿日やURL内の日付は含めません。年月日、月日、スラッシュ・ハイフンの年月日、スラッシュの月日、全角数字、今日・明日・明後日に対応します。
- 日付の意味までは推測せず、検出できた日付で判定します。日付が画像・添付資料だけにある場合は14日ルールです。
- 表示期間を過ぎてもGmailのメールは削除しません。既存の2か月のシート保存ルールは維持しますが、本文の日付がまだ有効なClassroomのお知らせは例外として保存を継続します。過去に削除済みの行をこの変更だけで復元することはありません。
# 完成済み表示一覧

`CompleteDisplaySnapshot.gs` は、同期時に課題と大学通知の全件一覧を圧縮し、ユーザー別に保存します。長い課題本文とお知らせ本文は初期一覧に含めず、詳細を選択した時に読みます。本文検索は従来どおり保存済みのお知らせ本文を対象にします。

`表示一覧保存_A` / `表示一覧保存_B` のうち参照されていない方へ新しい一覧を書き、表示用シートへの書き込みとflushが成功した後に、一つのユーザープロパティで公開先を切り替えます。更新途中や中断時には前回の完成済み一覧を維持します。元メール・API保存先の変更や、表示のためのGmail/API取得は行いません。

圧縮一覧が96,000文字以内で保存容量に余裕がある場合は、8,000文字以下のユーザープロパティへも分割保存します。起動時はすでに取得した同じプロパティから読み、初期HTMLに全件を含めます。初期データが160,000文字を超える場合は先頭表示に戻し、残りを取得します。プロパティを使えない場合も、完成済み一覧シートの必要な範囲を一回で読みます。CacheServiceを消去してもこの保存済み一覧は残ります。

課題の完了・取消では一覧の状態世代を更新します。通知の既読・保存状態は利用者の最新状態を重ねます。保存先IDが異なる場合、壊れた参照情報、テストモードでは本番の保存済み一覧を使用しません。テスト日時は仮想データから従来と同じ処理で再生成します。
